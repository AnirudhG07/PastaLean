## P0 — REGRESSIONS (25): status — **19/25 FIXED** (2026-07-24)

Fixed with general, type-directed rules (not per-problem patches); PALC stays 88/0:
- **R1 (10/10 ✅)** — TypeInfer now stamps the list-vs-`Prod` unpack shape at *every* nesting level
  (`stampUnpackShape`, driven by the element type), and Desugar preserves it instead of blanket-forcing
  `Prod`; `pairwise` modeled as `list[(elem,elem)]`. Files: `TypeInfer/Solve.lean`, `TypeInfer/Rules.lean`,
  `PyGens/Transform/Desugar.lean`.
- **R3 (5/5 ✅)** — every condition position now shares one boolean-context treatment: the ternary
  (`IfExp`), comprehension `if`-filters, and the pure early-return `if` (`Head_If`) all wrap their test
  in `withPropCondition true`/`truthyConditionTerm`, so a `BoolOp`/bitwise there lowers to the `Bool`
  connective, not the value-form. Files: `PyGens/Basic.lean`, `PyGens/UseCases/{ListComp,FuncDef}.lean`.
- **R2 (4/9 ✅)** — the `t[a:b] = xs` slice-assignment was mis-typed as index-assignment
  (`t : list[list …]` → joined to `any`); now a slice target shares the RHS list's type. Fixes
  check-if-word-is-valid, reverse-pairs, find-permutation, next-greater-element-iii. File: `TypeInfer/Solve.lean`.

**Remaining 6 (deeper TypeInfer work):**
- **R2 residue (5)** — group-the-people, intervals-between-identical-elements, number-of-good-paths,
  number-of-same-end-substrings, lexicographically-smallest. Two root causes: (a) **comprehension
  scoping** — a comprehension reuses a loop-var name (`for i,v in enumerate(...)` then
  `[… for i,v in g.items()]`); the flat env conflates the two `v`s (`int ⊔ list[int] = any`), poisoning
  a defaultdict key → `Hashable PyAny`. Needs scoped inference for comprehension targets. (b) recursive
  nested-fn param (`find(x)`) used as an index should infer `Int`, not `.any` (usage-based param seeding).
- **R4 (1)** — maximum-difference-score-in-a-grid: `float('inf')` mixed with Int in `min/max`; folded
  into the T1 inf-sentinel theme (twin-aware `inf`→Float).
